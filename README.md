# ai_research

Зонтичный исследовательский проект: игры как управляемые среды для изучения
человекоподобного поведения ИИ-агентов.

Цель — не игры как продукты, а чистые эксперименты. Каждая игра — маленькая
сконструированная сцена (выбор, ненадёжный мир, дефицит информации), где модель
вынуждена вести себя «как живой персонаж в условиях неопределённости».
Логи партий — материал для анализа: что именно делает поведение модели более
живым и как это прививать через изменение весов локальной сети.

## Primary research goal

Главная цель текущей лабораторной линии — создать не процедурного игрового
агента и не одну всезнающую модель, а **составной искусственный организм**.
Разные AI-подсистемы выполняют функции разных человеческих подсистем, работают
на разных частотах, получают различную информацию, спорят, обучаются на
последствиях и влияют друг на друга. Подсистема не обязана быть отдельной
архитектурой сети: для смыслового мышления одна сильная LLM может работать в
нескольких изолированных контекстах, если эти контексты действительно не
подглядывают в рассуждение друг друга. Целостное человекоподобное поведение
должно возникать из их совместной истории, а не из таблицы заранее заданных
реакций.

Brain LLM остаётся основным смысловым «неокортексом». В текущей Юки эта же LLM
может независимо рассуждать как Heart и Head в двух свежих OpenCode child
sessions, а Will/Ego отдельно оценивает устойчивость намерения под давлением.
Периодическая Audience даёт независимую социальную оценку, а устойчивый
Character Core обусловливает все эти модели без таблицы обязательных реакций.
После этого основной контекст Юки видит позиции и разрешает конфликт. Spine CNN
отвечает за быстрое восприятие и координацию, Motor MLP — за рефлекторное
управление. Разделение функции определяется границей контекста, доступной
информацией, памятью и обратной связью, а не обязательным наличием разных типов
нейросетей.

Архитектура задаёт органы, каналы связи, доступную им информацию и условия
обучения, но не готовую личность. Желание не равно решению, решение не равно
действию, действие не равно результату, а результат не предписывает внутреннюю
оценку. Исследовательская гипотеза состоит в том, что согласованная личность
может возникнуть именно из взаимодействия ограниченных специализированных
подсистем.

## Структура

Текущая линия realtime-исследования — `gameserver`, `gameclient`, `gamelab`,
`gametable`: LLM Brain, temporal CNN Spine и MLP Motor. Единый архитектурный
контракт: [gamelab/ARCHITECTURE.md](gamelab/ARCHITECTURE.md).
`game1` и `game2` сохраняются как отдельные прежние исследования.

[`director/`](director/) — архив опыта моделей Brain: единый SQLite-датасет,
доказательная разметка поведения, реакции на стимулы директора и параметры
сравнения моделей. Первый кейс — Ами (GPT‑5.6 Luna, xhigh).

```
ai_research/
├── README.md          ← этот файл: общая идея и стек
├── AGENTS.md          ← краткие правила для агентов
├── CLAUDE.md          ← краткие правила для Claude
├── .gitignore
└── gameN/             ← отдельное исследование
    ├── README.md      ← детально: правила среды, гипотеза, что и как меряем
    └── AGENTS.md      ← (опционально) локальные правила разработки
```

Каждая подпапка `gameN/` — **независимое исследование** на общем стеке.
Подпапки самостоятельны: можно работать с одной, не трогая остальные.

- [`game1/`](game1/) — первая игра: web-only операторское приложение для
  запуска прогонов, снапшотов и лабораторных разборов. Подробности — в её
  `README.md`.
- [`game2/`](game2/) — платформер для исследования управления с фиксированным
  шагом времени: загружаемые карты, окно человека и real-time сокет модели.
- [`gameserver/`](gameserver/) — параллельная MMO-style лаборатория серверной
  архитектуры: автономный authoritative мир, World/Zone/Gateway, серверные
  мобы и 120-Hz telemetry. Она развивается независимо от Game2 Console и
  предназначена как фундамент будущего самостоятельного игрового мира.
- [`gameclient/`](gameclient/) — независимый CLI-клиент к публичному Gateway
  GameServer: passwordless lobby, session, snapshots и управление без TUI;
  текстовый вывод удобен человеку, `--json` — агентам и скриптам.
- [`gamelab/`](gamelab/) — отдельная лаборатория иерархического обучаемого
  управления: LLM задаёт стратегическую цель, Spine CNN и Motor MLP обучаются
  самостоятельно замыкать realtime motor loop через GameClient Host.
- [`gametable/`](gametable/) — рабочий стол OpenCode для LLM-лаборанта:
  директор ставит задачу в диалоге, а на столе лежат руководства по игровому
  клиенту, основной лаборатории, advanced-настройкам и будущим plugins — без
  заранее записанного решения.

## Стек

| Компонент | Детали |
|-----------|--------|

на будущее — интерфейс держим расширяемым, но не реализуем сейчас.

## Как работать

1. Прочитай этот README — общая идея и стек.
2. Перед работой с конкретной игрой читай **её** `gameN/README.md` (и при
   наличии `gameN/AGENTS.md`) — там правила среды, гипотеза и локальные
   соглашения.
3. **При работе внутри подпапки приоритет у её локальных файлов**, не у корневых.
   Решения одной игры не переноси в другую.
4. Корневые `AGENTS.md`/`CLAUDE.md` — краткие указатели для агентов, не
   дублируют детали.
