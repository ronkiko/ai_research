# 002 — Игровая лаборатория по изучению игровых механик

`gamelab_v1` — уже настроенная экспериментальная среда для исследования
игровых механик с помощью обучаемой модели.

Лаборатория подключена к той же авторитетной realtime-игре через собственный
GameClient-клиент. У игрового клиента лаборанта и у лаборатории отдельные пути
управления одной и той же игрой. Удобная физическая аналогия: к одной видеоигре
подключены два джойстика — один у лаборанта, второй у лаборатории.

Это описание устройства рабочего места, а не инструкция по выбору способа
решения задачи Директора.

## Что умеет лаборатория

Лаборатория через MCP позволяет:

- проверить связь с живой игрой и готовность модели;
- получить описание возможностей лаборатории;
- посмотреть метаданные текущего model checkpoint;
- посмотреть и изменить reward-настройки;
- запустить обучение модели;
- наблюдать bounded историю и метрики обучения;
- отменить обучение;
- запустить frozen VERIFY;
- наблюдать результаты VERIFY;
- запустить текущую модель в живой игре;
- наблюдать и отменять такой запуск.

Длительные операции асинхронны: стартовый tool возвращается сразу, а ход
эксперимента читается отдельным status tool. Одновременно лаборатория выполняет
только одну активную длительную операцию.

## Инструменты лаборатории

Ожидаются MCP tools:

- `gamelab_v1_health`
- `gamelab_v1_describe`
- `gamelab_v1_model_info`
- `gamelab_v1_reward_get`
- `gamelab_v1_reward_set`
- `gamelab_v1_training_start`
- `gamelab_v1_training_status`
- `gamelab_v1_training_cancel`
- `gamelab_v1_verify_start`
- `gamelab_v1_verify_status`
- `gamelab_v1_verify_cancel`
- `gamelab_v1_run_start`
- `gamelab_v1_run_status`
- `gamelab_v1_run_cancel`

Начинай с `health` и `describe`.

## Reward-настройки

Текущий reward-инструмент содержит измеряемые компоненты:

- `distance_progress_scale` — вес уменьшения расстояния до текущей цели;
- `step_cost` — стоимость одного motor-step;
- `success_bonus` — терминальный бонус успешного завершения;
- `timeout_penalty` — терминальный штраф timeout;
- `stopped_near_goal_bonus` — дополнительный сигнал за остановленное состояние
  в заданной окрестности цели;
- `near_goal_radius` — радиус этой окрестности.

Эти параметры формируют обучающий сигнал, но не задают управляющие действия.
Изменения применяются к последующим training episodes.

## Обучение

`training_start` принимает число эпизодов, optional `target_x`, режим
`fresh`, seed и лимит времени эпизода.

Если `target_x` не задан, лаборатория сама выбирает цели в поддерживаемом
диапазоне текущего эксперимента.

`training_status` возвращает текущее состояние, количество завершённых
эпизодов, последний результат и bounded `recent_episodes` с reward/loss и
другими метриками.

## VERIFY

`verify_start` запускает frozen-weight проверку текущего checkpoint. Во время
VERIFY веса не обучаются. Успех или неуспех VERIFY — наблюдаемый результат
эксперимента, а не гарантия лаборатории.

## Экспериментальный запуск модели

`run_start` запускает текущую модель в живой игре с заданной поддерживаемой
целью. `run_status` показывает наблюдаемое состояние этого запуска.
`run_cancel` останавливает активный запуск.

Лабораторный MCP не предоставляет лаборанту файловый доступ к реализации
лаборатории. Для обычной исследовательской работы используй инструменты этого
руководства, а не shell-скрипты или исходники соседних директорий.
