# 01 / 15 — Единое тело Юки: цель и договор рефакторинга

Статус: действующий договор серии. Этапы 02–15 реализованы. Серия остаётся
не принятой до повторной manual-проверки Stage 15 и обязательной
live/manual/scientific evidence. После этапа
11 был исправлен browser realtime path, а проверка этапа 14 выявила следующий
разрыв: несколько независимых observer loops повторно poll-ят один и тот же
authoritative World и периодически делают Host cache stale под нормальной
нагрузкой.

Исходное основание сохраняется: персонаж управляет собственным телом в
визуальной новелле; обучение Spine и Motor доступно через MCP без файловой
системы и shell для LLM. Каждый пронумерованный документ задаёт один
последовательный патч/коммит серии. Реализация очередного этапа сама по себе не
означает приёмку всей серии.

## Вывод по текущему репозиторию

Сейчас GameTable меняет `scene_id` через свой WorldReducer, а GameServer считает
отдельного одномерного игрока. Рендер выбирает декорацию/позу из VN-сцены.
GameLab содержит полезное ядро обучения и контроля, но его интерфейс описывает
отдельный лабораторный стенд. Такое разделение не обеспечивает одно тело Юки.

Сохраняем LLM → temporal CNN Spine (10 Гц) → Motor (60 Гц) → физика (120 Гц),
независимые Heart/Head, review, журнал намерений и подтверждение внешних эффектов.
Меняем владение положением, интерфейсы действий и источник изображения.

## Цель

Юки разговаривает с Директором, сама формирует намерения, перемещается между
`hallway`, `laboratory`, `training/flat_run`, подходит к своему столу, работает
и обучает управление **тем же телом, которое видно в shell новеллы**.
`laboratory.workstation` становится объектом/местом взаимодействия внутри
`laboratory`, а не второй системой координат или независимой локацией.

Речь, отношения и личные предпочтения продолжаются при смене зоны. Задержка
LLM, review, закрытый браузер и медленный renderer не останавливают физику.
Навигационный MCP не является инструментом прямой установки `scene_id`.

Дополнение к исходному плану: [патч 10](10-director-escort.md) добавляет цикл дня
и явно алгоритмическое сопровождение Директора; первый аудит вынесен в 11.
Обучение за учителем отложено, существующее обучение Motor/Spine из 08 сохраняется.

## Почему серия расширена после этапа 11

Детерминированные проверки 11 прошли, но ручной browser-сценарий не был принят.
Исправление manual gate позволило реально сдвинуть Директора и Юки, после чего
проявилась системная проблема: GameTable одновременно обслуживает VN, browser
input, синхронно читает Host state и публикует RenderFrame. Browser key-repeat
превращается в поток request/response команд, чтение состояния конкурирует с
управлением, а физический runtime сейчас может форсировать durable checkpoint
на каждый применённый input. Результат — задержка визуального отклика и
transport timeout при работающей физике.

Это не повод переносить authoritative world в JavaScript. Новое видение делит
интернет-интерфейс человека и ядро игры:

```text
Internet Browser
      ↕  Socket.IO / HTTPS
Player Gateway (Node.js)
      ↕
GameClient Host[human]
      ↕
GameServer / authoritative World (Python)

LLM → Spine → Motor → GameClient Host[yuki] ───────────────┘
```

`Player Gateway` — внешний presentation/input gateway обычного игрока. Он
раздаёт web UI/assets, держит browser sessions, принимает keyboard/mouse/touch,
coalesces и ограничивает human input, формирует/транслирует RenderFrame и
обслуживает reconnect. Он не хранит authoritative coordinate/velocity, не
считает physics/collision/portal outcome и не управляет Юки.

`GameClient Host` остаётся одной реализацией. Для разных actors запускаются
отдельные instances/sessions: например `Host[human]` и `Host[yuki]`; отдельные
кодовые базы HumanHost/HumanoidHost не вводятся. Юки, Organism, navigation,
TRAIN/VERIFY/RUN и физический мир продолжают работать при полном отсутствии
Player Gateway. Его отказ означает потерю human web UI, а не остановку мира.

Этап 12 исправил realtime Host↔World boundary без Node. Этап 13 ввёл
Player Gateway. Этап 14 перевёл production browser world/input path и
GameTable web shell на Gateway, добавил deployment hardening и расширил
детерминированный gate до A1–A13. Ручная проверка 14 подтвердила сам gameplay
vertical, но показала периодический `authoritative Host state is stale`.
Этап 15 ввёл один shared `WorldStateHub` внутри GameServer Gateway:
один authoritative read stream от World и fan-out latest state всем Hosts и
internal readers без нового daemon. Полная серия всё ещё требует живых
доказательств, перечисленных в acceptance.

## Целевая структура и владельцы

| Компонент | Ответственность | Чего здесь нет |
| --- | --- | --- |
| `gameserver/` | Физический kernel, размеры/границы/коллизии, тела, зоны, ticks, физические transfer receipts | LLM, личность, reward, выбор цели, рисование, встроенный NPC-рулевой |
| `world/` (новый) | Каталог локаций/дверей/объектов, условия действий, navigation jobs, семантические взаимодействия, `navigation_v1` MCP | Motor effort, скрытый обход controller, собственная копия физического положения |
| `organism/` (из GameLab) | Spine/Motor, сенсоры, control executor, обучение, сертификаты, артефакты, `learning_v1` MCP | VN-сценарий, разговор, доступ LLM к файлам |
| `gameclient/` | Host: транспорт, идентичность сессии, последовательности и право записи актуатора; одна реализация, отдельный instance/session на actor | Решение о прибытии или об успешном обучении |
| `graphics/` | Языково-независимый RenderFrame contract и проверяемые правила проекции authoritative world | Физический шаг, переход зоны, human input |
| `player-gateway/` (новый) | Node.js internet-facing gateway: web assets, Socket.IO sessions, human input coalescing/rate limits, RenderFrame delivery | Physics authority, координаты как команда, Spine/Motor, управление Юки |
| `gametable/` | Личность, диалог, память, решения, исполнитель утверждённых действий и VN state | Авторитетное physical location, realtime human transport, низкоуровневое руление |
| `director/` | Архив и измерения | Автоматическая память персонажа |

Это границы модулей и API, а не требование co-location или немедленно создать
отдельный daemon на каждый модуль. `gameserver/` и `gameclient/` образуют
настоящую сетевую границу: GameServer может жить на VPS A, `Host[human]` +
Player Gateway на VPS B, а `Host[yuki]` + Organism/Spine/Motor — на отдельной
GPU machine/VPS C. Оба Host используют одну codebase и подключаются к одному
GameServer Gateway как независимые sessions.

WorldStateHub остаётся внутри server-side Gateway; web/AI nodes не получают
прямой World/Physics access. Single-machine launcher — development convenience,
не нормативная production topology. Подробный deployment contract:
[distributed runtime](../../deployment/distributed-runtime.md).

Физика и control executor живут независимо от HTTP/LLM; transport поток физики
не ждёт потребителя. Локальная Host-facing граница сохраняется.

```text
Director → appraisal → CharacterDecision + ActionProposal → ActionExecutor
                                            │
                          ┌─────────────────┴────────────────┐
                          ▼                                  ▼
                  navigation_v1 MCP                    learning_v1 MCP
                  world / goal jobs                    organism / schools
                          └───────────→ Spine → Motor ───────┐
                                                            ▼
                                                   Host → physics
                                                            │
                                  ┌─────────────────────────┴──────────┐
                                  ▼                                    ▼
                        measured observations                 graphics → shell
                                  │
                         journal → memory → narration
```

## Правила, которые серия обязана обеспечить

**A1 — одно тело.** `character_id → embodiment_id → entity_id` — сохраняемая
привязка. Все три локации используют её. Положение и `zone_id` принадлежат
физическому миру. GameTable и graphics хранят только помеченное наблюдение.

**A2 — режим управления явный.** В learned navigation/TRAIN/VERIFY/RUN LLM
выбирает локацию/объект/задачу, World задаёт семантические цели, движение выполняют
CNN/Motor без процедурного fallback. По дополнительному решению Директора
патч 10 вводит отдельный временный `scripted_escort` для сопровождения человека.
Он не обучает сеть, не подменяет learned controller и не засчитывается как навык.
Скрытые снапы положения/скорости запрещены в обоих режимах.

**A3 — переход подтверждён.** Касание portal trigger автоматически запускает
проверенный перенос тела в другую зону с receipt; кнопка ↑ и остановка не нужны.
Physics обнаруживает и пересечение trigger за tick; повторное касание в точке
появления не вызывает обратный перенос без нового входа. Этот
явный portal transfer не объявляется непрерывным шаганием между несмежными
картами. MCP accepted, нарратив и переключение картинки не являются receipt.

**A4 — физика независима.** Ни MCP, ни renderer, ни LLM не задают темп 120 Гц.
TRAIN/VERIFY/RUN используют один executor; пропуски ticks регистрируются.
Действуют отдельные world ticks, wall-clock watchdog и narrative time.

**A5 — обучение через MCP.** Юки может начать обучение Motor и Spine, наблюдать,
отменять, проверять и явно выбирать навык через типизированные инструменты.
LLM не получает пути, shell, код тренера, pickle или право загружать произвольные
модели. Backend хранит артефакты по непрозрачным IDs и проверяет совместимость.

**A6 — доступ по смыслу.** Навигация доступна в коридоре, лаборатории и на курсе,
а не только за ноутбуком. Обычные appraisal/narration/review остаются без tools.
Одобренное персонажем намерение исполняется отдельным контекстом. Работа за
столом и физическая тренировка имеют разные условия доступа.

**A7 — научная честность.** Сертификаты, hash и независимый VERIFY сохраняются.
Успех демонстрации не заменяет многосидовую оценку. Декоративная ходьба/посадка
не выдаётся за обученный суставной контроль; романтика не меняет reward/экзамен.

**A8 — восстановление.** Durable action/job IDs, idempotency, статусы uncertain,
reconciliation и fencing защищают от второго переноса/обучения после сбоя.
Нет общей атомарной транзакции MCP и VN; внешние факты сохраняют силу даже при
ошибке narrate/review. Disconnect не доказывает отмену.

**A9 — рендер отражает мир.** Один avatar binding, кадры со ссылками на world
snapshot, отсечение устаревших epochs и запрет интерполяции между зонами.
Renderer не является сенсором CNN по умолчанию. Первый viewport — примитивный
2D-вид с одной осью X: terrain/occupancy, одинаковый диапазон 0…1000 (1001 ячейка),
заглушки P/D с возможностью замены PNG. Физика хранит непрерывные coordinates;
слои — её проекция. Снизу VN-окно последней реплики обоих участников, ввод в sidebar.

**A10 — завершённый переход.** Активный запуск, MCP, CI и руководства больше не
зависят от `gamelab/`; школы, данные и сертификаты не теряются при переносе.
Старые социальные протоколы не возвращаются в активный персонаж.

**A11 — день и сопровождение.** В начале первого дня и после завершённого сна
Юки размещается у EXIT в hallway (якорь x=0) явным day-start receipt. В первый
день рядом в x=1 ждёт отдельный actor Директора. Через 300 активных реальных
секунд первого разговора Юки завершает реплику просьбой проводить до laboratory
(телепорт около x=500). После явного согласия человека и старта escort модальный
VN-диалог закрывается и включается ручное управление. Browser arrows/GUI управляют
только Директором; касание двери переносит каждого actor отдельно.
Обучение следованию по данным человека — будущий план после приёмки этой серии.

**A12 — интернет-игрок отделён от ядра.** Browser общается с physical world только
через Node.js Player Gateway и выделенный `Host[human]`. Browser не знает
GameServer address, не задаёт coordinate/velocity и не открывает actuator Юки.
Повторяющиеся keyboard events coalesce до текущего human input state; внешний
flood не превращается в такое же число physics commands. RenderFrame и input
имеют независимые bounded streams.

**A13 — realtime и failure isolation.** Physics ticks, Organism и `Host[yuki]`
не зависят от Player Gateway, browser FPS, Socket.IO или GameTable turn latency.
Медленный/отключённый клиент теряет промежуточные frames, а не тормозит world.
Disconnect/blur освобождает human effort через lease/watchdog. Restart или падение
Player Gateway не телепортирует actors, не сбрасывает навыки и не останавливает
Юки; reconnect начинает с fresh authoritative state.

**A14 — один authoritative observation fan-out.** Production read path
Gateway→World имеет один shared `WorldStateHub` с bounded cadence и latest-only
cache независимо от числа Hosts, browser clients и server-side observers.
Snapshot, per-entity observation и controller fence одного frame относятся к
одному world epoch/tick/revision. Downstream freshness отражает end-to-end age
исходного World frame и не обнуляется простым чтением старого cache.
`scripted_escort` не создаёт отдельный direct World snapshot polling loop.

## Объём этой серии

Первая версия нового мира использует честно обозначенную физику `flat_1d`:
одна ось движения, длина, границы/стены, объекты и порталы в трёх зонах. Фон
может быть двумерным, но это не доказательство 2D/3D тела. Формат physics profile
версируется; неподдерживаемая гравитация/ось отклоняется, а не игнорируется.
Настоящая гравитация, многосуставный гуманоид и новые сенсоры требуют следующей
версии физики, обучения и сертификатов. В этой серии нельзя объявлять их готовыми.

Посадка за ноутбук — подтверждённое семантическое взаимодействие после подхода,
отображаемое анимацией. Политика ног/суставов для посадки пока не исследуется.
Долгосрочное изменение характера отдельной системой не входит в серию; текущая
память и диалог сохраняются, добавляется история наблюдённых действий тела.

## Первый навык без логического тупика

Новый обычный сюжет начинается в `hallway`. Возможны заранее подготовленные
сертифицированные базовые навыки, но они явно обозначаются, не считаются вновь
обученными. Если их нет, `navigate` возвращает `skill_missing`. Отдельно принятый
`scripted_escort` из патча 10 позволяет сюжетное сопровождение без навыка,
но не исправляет readiness модели и не отменяет необходимость обучения.

Предусмотреть отдельную процедуру `training_prepare`: Директор явно разрешает
ассистированное размещение тела в `training/flat_run` для первого обучения.
Backend выполняет setup transfer с отдельным типом receipt. Это не navigation
success, не навык и не тихая телепортация. Та же Юки и тот же entity остаются
видимыми в новелле. Дальнейшее обучение Motor/Spine проводит LLM через MCP.
Разрешение на setup не даёт права на произвольные переносы из обычного диалога.

## Общая приёмка

Дополнительно пройти сюжетное сопровождение из EXIT человеком через browser/GUI
и новое утро после сна; scripted demo не заменяет проверки learned вертикали.

Обязательная вертикаль: разговор в hallway → Юки принимает/сама предлагает
поход → MCP navigation → видимый физический подход и transfer → laboratory →
подход к workstation и работа → training/flat_run → обучение/проверка →
возврат той же Юки с тем же опытом и новым навыком. Проверить отказ, отсутствие
навыка, заблокированный путь, остановку controller, сбой MCP, рестарт и reconnect.

Отдельно пройти путь без начального навыка через явный setup, затем настоящий
обученный выход с курса. Приёмка должна различать физическую достигнутость,
наблюдение результата моделью и корректный рассказ о нём.

После реализации патча 15 финальный аудит проверяет каждый A1–A14 по коду и воспроизводимым доказательствам, включая реальный
browser → Player Gateway → Host[human] → GameServer путь и bounded shared
Gateway→World observation rate. Если научный, live LLM или human web-сценарий
не пройден, серия не объявляется принятой по одним unit tests.
