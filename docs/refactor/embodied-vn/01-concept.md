# 01 / 10 — Единое тело Юки: цель и договор рефакторинга

Статус: план, не выполненный рефакторинг. Основание — уточнение Директора:
персонаж управляет собственным телом в визуальной новелле; обучение Spine и
Motor остаётся доступным через MCP, без файловой системы и shell для LLM.
Каждый пронумерованный документ задаёт один будущий коммит. Коммит, добавивший
эти документы, сам по себе не означает выполнения этапов 02–10.

## Вывод по текущему репозиторию

Сейчас GameTable меняет `scene_id` через свой WorldReducer, а GameServer считает
отдельного одномерного игрока. Рендер выбирает декорацию/позу из VN-сцены.
GameLab содержит полезное ядро обучения и контроля, но его интерфейс описывает
отдельный лабораторный стенд. Такое разделение не обеспечивает одно тело Юки.

Сохраняем LLM → temporal CNN Spine (10 Гц) → Motor (60 Гц) → физика (120 Гц),
независимые Heart/Head, review, журнал намерений и подтверждение внешних эффектов.
Меняем владение положением, интерфейсы действий и источник изображения.

## Цель

Юки разговаривает с Директором, сама формирует намерения, перемещается между
`hallway`, `laboratory`, `training/flat_run`, подходит к своему столу, работает
и обучает управление **тем же телом, которое видно в shell новеллы**.
`laboratory.workstation` становится объектом/местом взаимодействия внутри
`laboratory`, а не второй системой координат или независимой локацией.

Речь, отношения и личные предпочтения продолжаются при смене зоны. Задержка
LLM, review, закрытый браузер и медленный renderer не останавливают физику.
Навигационный MCP не является инструментом прямой установки `scene_id`.

## Целевая структура и владельцы

| Компонент | Ответственность | Чего здесь нет |
| --- | --- | --- |
| `gameserver/` | Физический kernel, размеры/границы/коллизии, тела, зоны, ticks, физические transfer receipts | LLM, личность, reward, выбор цели, рисование, встроенный NPC-рулевой |
| `world/` (новый) | Каталог локаций/дверей/объектов, условия действий, navigation jobs, семантические взаимодействия, `navigation_v1` MCP | Motor effort, обход CNN, собственная копия физического положения |
| `organism/` (из GameLab) | Spine/Motor, сенсоры, control executor, обучение, сертификаты, артефакты, `learning_v1` MCP | VN-сценарий, разговор, доступ LLM к файлам |
| `gameclient/` | Host: транспорт, идентичность сессии, последовательности и право записи актуатора | Решение о прибытии или об успешном обучении |
| `graphics/` (новый) | Проекция подтверждённого мира в RenderFrame, камера, слои, позы/анимационные параметры | Физический шаг, переход зоны, научные policy observations |
| `gametable/` | Личность, диалог, память, решения, исполнитель утверждённых действий, browser shell | Авторитетное `scene_id`, физическая телепортация, низкоуровневое руление |
| `director/` | Архив и измерения | Автоматическая память персонажа |

Это границы модулей и API, не требование немедленно создать шесть новых демонов.
World и graphics допускается разместить в одном application host разными
модулями. Физика и control executor живут независимо от HTTP/LLM; transport
поток физики не ждёт потребителя. Публичная граница Host сохраняется.

```text
Director → appraisal → CharacterDecision + ActionProposal → ActionExecutor
                                            │
                          ┌─────────────────┴────────────────┐
                          ▼                                  ▼
                  navigation_v1 MCP                    learning_v1 MCP
                  world / goal jobs                    organism / schools
                          └───────────→ Spine → Motor ───────┐
                                                            ▼
                                                   Host → physics
                                                            │
                                  ┌─────────────────────────┴──────────┐
                                  ▼                                    ▼
                        measured observations                 graphics → shell
                                  │
                         journal → memory → narration
```

## Правила, которые серия обязана обеспечить

**A1 — одно тело.** `character_id → embodiment_id → entity_id` — сохраняемая
привязка. Все три локации используют её. Положение и `zone_id` принадлежат
физическому миру. GameTable и graphics хранят только помеченное наблюдение.

**A2 — движение обучено.** LLM выбирает локацию/объект/задачу. World разбивает
маршрут только на семантические выходы и цели. Подход к двери выполняет CNN/Motor;
в цепочке нет PID, timed move, scripted steering, скрытого снапа до цели.

**A3 — переход подтверждён.** На физическом подходе к порталу проверяются
условия, затем мир атомарно переносит тело в другую зону с receipt. Этот
явный portal transfer не объявляется непрерывным шаганием между несмежными
картами. MCP accepted, нарратив и переключение картинки не являются receipt.

**A4 — физика независима.** Ни MCP, ни renderer, ни LLM не задают темп 120 Гц.
TRAIN/VERIFY/RUN используют один executor; пропуски ticks регистрируются.
Действуют отдельные world ticks, wall-clock watchdog и narrative time.

**A5 — обучение через MCP.** Юки может начать обучение Motor и Spine, наблюдать,
отменять, проверять и явно выбирать навык через типизированные инструменты.
LLM не получает пути, shell, код тренера, pickle или право загружать произвольные
модели. Backend хранит артефакты по непрозрачным IDs и проверяет совместимость.

**A6 — доступ по смыслу.** Навигация доступна в коридоре, лаборатории и на курсе,
а не только за ноутбуком. Обычные appraisal/narration/review остаются без tools.
Одобренное персонажем намерение исполняется отдельным контекстом. Работа за
столом и физическая тренировка имеют разные условия доступа.

**A7 — научная честность.** Сертификаты, hash и независимый VERIFY сохраняются.
Успех демонстрации не заменяет многосидовую оценку. Декоративная ходьба/посадка
не выдаётся за обученный суставной контроль; романтика не меняет reward/экзамен.

**A8 — восстановление.** Durable action/job IDs, idempotency, статусы uncertain,
reconciliation и fencing защищают от второго переноса/обучения после сбоя.
Нет общей атомарной транзакции MCP и VN; внешние факты сохраняют силу даже при
ошибке narrate/review. Disconnect не доказывает отмену.

**A9 — рендер отражает мир.** Один avatar binding, кадры со ссылками на world
snapshot, отсечение устаревших epochs и запрет интерполяции между зонами.
Renderer не является сенсором CNN по умолчанию.

**A10 — завершённый переход.** Активный запуск, MCP, CI и руководства больше не
зависят от `gamelab/`; школы, данные и сертификаты не теряются при переносе.
Старые социальные протоколы не возвращаются в активный персонаж.

## Объём этой серии

Первая версия нового мира использует честно обозначенную физику `flat_1d`:
одна ось движения, длина, границы/стены, объекты и порталы в трёх зонах. Фон
может быть двумерным, но это не доказательство 2D/3D тела. Формат physics profile
версируется; неподдерживаемая гравитация/ось отклоняется, а не игнорируется.
Настоящая гравитация, многосуставный гуманоид и новые сенсоры требуют следующей
версии физики, обучения и сертификатов. В этой серии нельзя объявлять их готовыми.

Посадка за ноутбук — подтверждённое семантическое взаимодействие после подхода,
отображаемое анимацией. Политика ног/суставов для посадки пока не исследуется.
Долгосрочное изменение характера отдельной системой не входит в серию; текущая
память и диалог сохраняются, добавляется история наблюдённых действий тела.

## Первый навык без логического тупика

Новый обычный сюжет начинается в `hallway`. Возможны заранее подготовленные
сертифицированные базовые навыки, но они явно обозначаются, не считаются вновь
обученными. Если их нет, `navigate` возвращает `skill_missing`.

Предусмотреть отдельную процедуру `training_prepare`: Директор явно разрешает
ассистированное размещение тела в `training/flat_run` для первого обучения.
Backend выполняет setup transfer с отдельным типом receipt. Это не navigation
success, не навык и не тихая телепортация. Та же Юки и тот же entity остаются
видимыми в новелле. Дальнейшее обучение Motor/Spine проводит LLM через MCP.
Разрешение на setup не даёт права на произвольные переносы из обычного диалога.

## Общая приёмка

Обязательная вертикаль: разговор в hallway → Юки принимает/сама предлагает
поход → MCP navigation → видимый физический подход и transfer → laboratory →
подход к workstation и работа → training/flat_run → обучение/проверка →
возврат той же Юки с тем же опытом и новым навыком. Проверить отказ, отсутствие
навыка, заблокированный путь, остановку controller, сбой MCP, рестарт и reconnect.

Отдельно пройти путь без начального навыка через явный setup, затем настоящий
обученный выход с курса. Приёмка должна различать физическую достигнутость,
наблюдение результата моделью и корректный рассказ о нём.

Финальный патч заново читает этот файл, проверяет каждый A1–A10 по коду и
воспроизводимым доказательствам, исправляет остаточные нарушения. Если научный
или живой сценарий не пройден, серия не объявляется принятой по одним unit tests.
