# Лор игры

Здесь описывается **мир игры**: его история, персонажи, отношения, места,
сюжетные возможности и авторский замысел. **Технической информации в этом
разделе нет:** устройство программ, модели, протоколы, команды, численные
настройки и планы реализации находятся в других разделах репозитория.
Правила ниже — редакционный порядок сохранения и изменения лора.

**Действующая редакция: [L001 — Общее начало](editions/L001.md).**
Это единственный указатель на актуальный канон. Читать следует выбранные
в редакции тексты, а не все файлы каталога подряд.

## Что считается каноном

Редакция — зафиксированный набор версий смысловых тем. У каждой темы есть
постоянное имя, у каждого значимого положения — постоянный смысловой ID.
Определение положения живёт только в своей теме; другие тексты ссылаются
на него, не пересказывают его как новое правило.

Первая редакция содержит одну тему — основы мира. Новые темы выделяем по
необходимости: персонажи, места, история. Не дробим каждый абзац в отдельный
документ и не создаём заранее пустую энциклопедию.

В текстах различаем:

- **Основа мира** — принятые автором положения.
- **Сюжетная возможность** — допустимое развитие, которое ещё не произошло.
- **Открытый вопрос** — смысл пока не определён; пробел не разрешает считать
  догадку каноном.

Лор не является журналом конкретного прохождения. Возможная любовь не означает,
что Юки уже влюблена; описанная возможность обучения не означает освоенный навык.
Редакция также не подтверждает готовность игры или её отдельных возможностей.

## Как менять лор без переписывания всего раздела

1. Назвать изменяемые смысловые ID и оформить предложение по
   [шаблону изменения](changes/TEMPLATE.md). Привязка к серии, например
   `0.main.3`, — основание изменения, а не номер редакции лора.
   Одна серия может не менять лор или породить несколько его редакций.
2. Найти затронутые темы по списку зависимостей действующей редакции.
   Проверить именно их; добавляя новое смысловое использование, обязательно
   добавлять зависимость. Список — редакционная дисциплина, не автоматическая
   гарантия отсутствия противоречий.
3. Создать следующую версию только изменяемой темы, например
   `topics/foundation/02.md`. Сохранить смысловые ID. Удалённый смысл явно
   отметить как отменённый или заменённый; его ID не выдавать другому смыслу.
   Неизменённые темы остаются в прежних версиях.
4. Создать следующую редакцию `editions/L002.md` с **полным списком** выбранных
   версий тем, их зависимостей и ссылкой на запись изменения. Читатель получает
   цельный канон без последовательного применения всех прошлых поправок.
5. После явного принятия автором сменить указатель действующей редакции в этом
   README. До этого предложение и новые тексты остаются черновиком и не меняют
   канон. Прямая просьба автора принять конкретное изменение достаточна.

Принятые редакции, выбранные ими тексты и записи изменений сохраняются.
Смысловые исправления всегда создают новую версию. Опечатки и сломанные ссылки
можно исправлять на месте, если смысл не меняется.

## Правила против накопления противоречий

- **Один смысл — одно место определения.** В обзорах использовать ссылки;
  художественные сцены не должны незаметно вводить общие законы мира.
- **История и пересмотр различаются.** Событие продолжает прежнюю историю;
  реткон меняет то, что считалось истинным. Для реткона явно написать, какое
  прошлое сохраняется и какое заменяется. Не объяснять авторское исправление
  выдуманным событием без отдельного решения автора.
- **Ссылки фиксируют версию.** Пример: `foundation@01 / WORLD-01`.
  Старые редакции не должны начинать означать другое после обновления.
- **Каждая тема перечисляет смысловые зависимости.** В редакции они повторяются
  как компактная карта влияния. Зависимость указывает конкретные ID; если
  зависит вся тема, это пишется явно.
- **Разрешение противоречий не определяется датой файла.** В действующем каноне
  действует выбранная редакцией версия. При конфликте внутри неё оформить
  исправление; не выбирать удобное утверждение молча.
- **Новая редакция не переписывает старое прохождение автоматически.** Запись
  изменения указывает: только новые истории, продолжение прежних или отдельное
  решение автора о переносе. Пока такого решения нет, прежняя история остаётся
  в своей редакции.

## Короткая проверка перед принятием

- Изменение описано как смысл мира, без технических подробностей.
- У каждого нового положения есть одно место определения и ID.
- Все выбранные версии тем перечислены; ссылки ведут на существующие тексты.
- Для каждого изменённого ID проверены перечисленные зависимые темы;
  итог записан, в том числе если правка им не понадобилась.
- Возможности не выданы за произошедшие события; открытые вопросы не закрыты
  случайной формулировкой.
- Указаны последствия для прежних историй и решение автора.
