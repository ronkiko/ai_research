# game2: управление в физическом мире

`game2` — отдельное исследование в рамках `ai_research`. Здесь мы изучаем не
решение статической логической функции, а управление агентом во времени. Агент
должен понять физику простого платформера и подобрать последовательность
действий, которая приводит к результату.

На первом этапе игра запускается вручную. Нейросеть, датчики и оркестратор будут
подключаться после того, как физическая среда станет воспроизводимой и удобной
для лабораторных экспериментов.

## Игровая задача

Мир изображён сбоку. В нём есть ровная поверхность, затем яма, а после ямы —
продолжение поверхности. Игрок — квадрат размером `64x64` пикселя. Он начинает
слева от ямы и должен оказаться на земле справа от неё.

Задача требует именно разбега. Если игрок стоит на месте, подпрыгивает и только
потом нажимает вправо, он не получает горизонтального движения от прыжка. Игрок
не летит как самолёт: чтобы перелететь яму, нужно заранее набрать скорость на
земле и затем вовремя прыгнуть. Горизонтальная скорость, набранная до прыжка,
сохраняется в воздухе.

## Текущая ручная версия

Запуск:

```bash
cd game2
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python engine.py
```

Управление:

- удерживать **Right** — разгоняться и двигаться вправо;
- отпустить **Right** на земле — постепенно тормозить, а не останавливаться мгновенно;
- нажать **Up** на земле — начать прыжок;
- повторное нажатие **Up** в воздухе ничего не делает;
- **R** — начать новую попытку;
- **Esc** — выйти.

В текущей ручной версии движения влево нет. Направление назад и симметричное
управление можно добавить позже, если они понадобятся эксперименту.

## Физика

Физика находится в `physics.py` и не зависит от Pygame. Метод
`World.step(right, jump)` продвигает мир ровно на один физический такт.

Используются следующие правила:

- физический такт — `120 Hz`, то есть `1/120` секунды;
- игрок разгоняется вправо с ограничением максимальной скорости;
- разгон действует и на земле, и в воздухе, если удерживается Right;
- после отпускания Right торможение действует только на земле;
- в воздухе горизонтальная скорость сохраняется, поэтому позднее нажатие Right
  не заменяет разбег;
- прыжок доступен только при контакте с землёй;
- прыжок задаётся вертикальным импульсом, после чего игрок поднимается,
  замедляется под действием гравитации и падает;
- приземлиться можно только на поверхность, которая действительно находится
  под игроком;
- падение в яму заканчивается столкновением с опасной поверхностью и смертью;
- успех фиксируется только после приземления на земле справа от ямы.

Параметры первой версии:

| Параметр | Значение |
|---|---:|
| Размер мира | `1200x640` |
| Высота поверхности | `y=360` |
| Яма | `x=500..760` |
| Ширина ямы | `260 px` |
| Нижняя опасная поверхность | `y=584` |
| Гравитация | `1800 px/s^2` |
| Скорость прыжка | `700 px/s` |
| Максимальная скорость вправо | `340 px/s` |
| Ускорение | `1800 px/s^2` |
| Торможение на земле | `1400 px/s^2` |

При максимальной скорости дальности прыжка достаточно, чтобы перелететь яму.
Но это не отменяет необходимости правильно выбрать момент прыжка: слишком ранний
или слишком поздний прыжок может закончиться падением.

## Время и воспроизводимость

Отрисовка отделена от физики. Окно обновляется примерно с частотой `60 FPS`, а
физика всегда выполняется фиксированными шагами `120 Hz`. Это позволяет повторять
одинаковые последовательности действий с одинаковым результатом и в будущем
подавать агенту состояние с заранее заданным временным разрешением.

После большой задержки runner ограничивает время догоняющей симуляции значением
`250 ms`, не увеличивая размер физического шага. Отброшенное реальное время
показывается в HUD. Поэтому текущая программа является лабораторной
semi-real-time системой, но ещё не гарантирует hard real-time дедлайны.

## Наблюдение для будущих датчиков

Функция `render_world` создаёт чистое изображение игрового поля размером
`1200x640`. В него не входят HUD, текст, FPS, тени или сглаживание. Это изображение
предназначено для будущих датчиков и должно быть единственным источником
визуальной информации агента: датчики не должны получать скрытые координаты
игрока или объектов напрямую.

Цвета первой версии:

| Объект | RGB |
|---|---|
| Пустота | `255,255,255` |
| Земля | `0,0,0` |
| Игрок | `0,102,255` |
| Опасная поверхность | `255,0,0` |

## Будущая AI-система

Планируемая система — это не один вызов модели на всю игру, а semi-real-time
контур управления:

```text
фиксированный тик физики
        |
        v
  изображение мира
        |
        v
 субагенты-датчики
        |
        v
 оркестратор и решение
        |
        v
 действия Right / Up
```

Субагенты могут специализироваться на разных признаках: положении игрока,
скорости, расстоянии до ямы, контакте с землёй, фазе прыжка и оценке времени до
приземления. Оркестратор будет собирать их выводы, учитывать задержки и выдавать
управляющее действие в установленный момент.

Начальная гипотеза — попробовать одну небольшую обучаемую сеть архитектуры
`2-4-1`. Она имеет смысл только для задачи с двумя заранее сжатыми признаками и
одним бинарным решением, например «прыгать сейчас или не прыгать». Если для
управления понадобится одновременно учитывать больше признаков или выбирать
несколько действий, архитектура будет расширена. Сначала предпочтительна самая
простая сеть, которая может решить задачу.

Важно разделять ответственность:

- физический движок является источником истины и сам обрабатывает столкновения,
  прыжок, падение и приземление;
- датчики видят только доступное агенту наблюдение;
- сеть выбирает действие, но не исправляет физику задним числом;
- оркестратор отвечает за расписание датчиков, согласование их выводов и
  соблюдение временного разрешения.

## События

`World.step` возвращает события только текущего такта:

- `die` — игрок коснулся опасной поверхности;
- `success` — игрок приземлился справа от ямы;
- `reset` — ручной перезапуск попытки.

Runner печатает игровые события в stdout в формате JSON Lines. Например:

```json
{"event":"die","reason":"damage_surface","tick":213,"episode":1}
```

После смерти часы симуляции продолжают идти, но действия игрока игнорируются до
нажатия `R`.

## Проверка

```bash
python -m unittest -v
```

Тесты проверяют устойчивость игрока на земле, вертикальный прыжок, управление в
воздухе, запрет двойного прыжка, однократную смерть, преодоление ямы с разбега и
воспроизводимость одинаковой последовательности действий.

## Файлы

- `physics.py` — детерминированная физика мира;
- `engine.py` — ручной Pygame runner и чистое изображение наблюдения;
- `test_physics.py` — тесты физики;
- `requirements.txt` — зависимости ручного runner.

`game2` развивается независимо от `game1`. Логика, модели и правила первой игры
не переносятся сюда автоматически.
